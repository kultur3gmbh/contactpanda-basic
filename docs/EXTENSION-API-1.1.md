# ContactPanda Basic integration API 1.1

Available from Basic 0.9.108; no Plus or WooCommerce dependency. Feature-detect the functions and `CONTACTPANDA_EXTENSION_API_VERSION` before use. PandaWoo owns products, orders, donations, sales and its product tab. Basic owns person data and search configuration; do not maintain another copy in product metadata.

- `contactpanda_search_people($query, $limit = 25, $offset = 0)` returns `contacts` and `total_items`. Limit is clamped to 1–50. Requires the existing ContactPanda view permission; returns `WP_Error` when denied. Uses the centrally selected fields and order-independent AND-word / OR-field semantics. Disabled fields never supply matches. Each token must occur within the same record. Email identity lookup/import deduplication remains independent of this UI preference.
- `contactpanda_get_person_profile($id)` returns `api_version`, `id`, `first_name`, `last_name`, `company_name`, `website`, `phone`, `biography`. Requires ContactPanda view permission. Existing canonical custom meta keys remain unchanged; existing biographies require no migration.
- `contactpanda_update_person_profile($id, $partial_values)` accepts only the six profile fields above (excluding ID/version), as strings. Returns true or `WP_Error`. Requires ContactPanda editing permission; empty strings explicitly clear a field. Reject unknown keys and missing contacts. Website accepts HTTP(S); biography uses `wp_kses_post`; names/phone/company label use plain text sanitization. Never pass order or product data. Standalone writes are atomic; the Groundhogg adapter uses one explicit `groundhogg/update-contact` ability and propagates errors.
- `contactpanda_get_person_biography_html($id)` is explicitly public biography output only; it never returns email, phone, CRM notes or tags. Formats the canonical biography, resolves registered shortcodes, filters unsafe output and returns an empty string when resolved visible text is empty (including non-breaking spaces). PandaWoo should register/render “Über die spendende Person” only if this result is nonempty. Public use of this function is an explicit publication of the biography, not of the complete profile.

HTTP callers must verify their own action-specific nonce before calling the update function. The function is a PHP integration contract, not a public unauthenticated endpoint. It does not grant extra roles/capabilities. The Basic biography editor verifies its nonce and rights itself. No Plus entitlement is required. Use `is_wp_error()` on every lookup/write response; do not report failed writes as saved.

The old `ContactPanda_Plugin::extension_*` methods remain supported. The generic Groundhogg ability adapter stays read-only; the profile write is narrowly scoped. Plus adds product/sales history through existing extension hooks, without registering another biography editor. Older Plus render hooks are removed by Basic to avoid duplicates during staggered updates.

## PandaWoo follow-up

Use these contracts in “Personendaten ergänzen” and the donor selection popup. Reuse Basic lookup instead of a local search implementation. Product-donor linkage and “Produkt nicht mit dieser Person verknüpfen” belong to PandaWoo. Keep the selected contact ID as the relationship key; do not copy the shared profile into the product. If Basic is absent, PandaWoo must feature-detect and retain its independent behavior without errors. Basic itself never assumes that PandaWoo or WooCommerce is installed.
